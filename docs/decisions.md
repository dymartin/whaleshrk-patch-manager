# Decision Record

Settled design calls and rationale. Prompt.md overrides are explicit.

| # | Decision | Why |
|---|---|---|
| 1 | Sequencer/morpher `.txt` state is compiler-owned; never in YAML, never round-tripped | Absent files leave stale arrays from the previously loaded preset, so "params.json only" forfeits determinism. Emitting a complete deterministic set restores it without exposing 800 files to musicians. Cost: on-device pattern edits are lost, accepted because note material comes from the DAW |
| 2 | Mod-source slots declared explicitly; default `-empty-` | Morpher sits in `m3` in stock ORHACK by default rather than by choice. Defaulting to empty means nothing reads morpher `.txt`, so nothing can go stale |
| 3 | Sample `.wav` files version-controlled in-repo | Positional sample references make folder contents load-bearing. Nothing weaker than owning the files keeps push reproducible |
| 4 | Push mirrors playback folders including deletions; `recordings/` and `media/samples/` excluded | Additive copy leaves stray files that shift every ordinal. The two excluded paths are device-written; `recordings/` is the only irreplaceable thing on the card |
| 5 | Pull ignores media | Push deletes card-side samples anyway, so pulling them first is churn. Capturing them would also break one-PR-per-song, since one new `.wav` shifts ordinals for every song using that folder |
| 6 | Plain git, no LFS | A missing LFS install yields pointer files instead of audio — a silently-wrong-sample failure, the exact class being designed out |
| 7 | Friendly kit aliases → `kit-N` | `kit-3` is a device identifier. Aliases also let kits move slot numbers without touching songs |
| 8 | Chains: friendly names, letters auto-assigned, binding persisted in push state | The device stores no chain names. Recording the binding at push time is what lets pull attribute drift correctly without pinning letters in YAML |
| 9 | MIDI note input always enabled | Enabling costs nothing (message-domain spigot, no DSP), and a chain with no note-reading module is unaffected. Channel assignment is #31 |
| 10 | Preset directory = numeric program prefix + sanitised song name; `Init` reserved | MEC Program Change indexes the alphabetical directory scan; prefixes and gap placeholders make YAML `program` direct and stable |
| 11 | Module key `slug(display)@source`; `+`→`-plus`; nested module dirs skipped | Unqualified, 34 keys covering 69 of 200 entries collide; qualified, none do. Unconditional qualification avoids a precedence rule. Both slug rules were found by measuring the real catalog, and the nesting rule also matches what `loadModuleDir` registers |
| 12 | Param names `slug(label)`, index suffix on collision | 16 of 66 built-ins repeat labels; pages don't disambiguate. Duplicates are structured per-voice repeats, so declaration order recovers them |
| 13 | Unmentioned params compile to catalog defaults, pinned per module version | Keeps song files short and output deterministic. Pinning stops an upstream default change from silently altering a song |
| 14 | CC mapping: per-module `midi:` block, channel implied from chain | Keeps a mapping next to what it drives, and makes the same CC on two chains independent without anyone thinking about it |
| 15 | Sends/master named at song level; send amounts per slot | Per-slot is what the device actually offers; chain-level would discard real capability |
| 16 | Repo layout `songs/`, `media/`, `.rig/` | Musicians see two directories |
| 17 | Drift baseline is the stored last-pushed snapshot | Recompiling instead would make a changed catalog default look like device drift, burying real edits in phantom diffs |
| 18 | Orphan presets adopted on pull; push refuses by default, `--force` deletes them. Refined by #52 | Safe default with an explicit path for disposable experiments |
| 19 | Transport is a narrow file interface | Mirroring semantics stay in one place. Per-backend reimplementation is where a subtle difference eats samples |
| 20 | Module versions pinned in `modules.lock`; upgrade explicit. **Supersedes Prompt.md** | Prompt.md specified auto-install on every push. Combined with #13 that changes a song's compiled output with no repo diff, so the rig could change between soundcheck and the set from an edit nobody in the band made |
| 21 | Python, ruamel.yaml, typer, httpx | Pull rewrites song files in place; ruamel round-trip preserves comments and formatting. Other stacks need manual CST work for the same result |
| 22 | Chain letters assigned capacity-aware rather than in strict declaration order. Exact rule in #30 | Capacity is asymmetric (A=3, B=4, C=3, D=4); strict order would make a musician reorder chains for a non-musical reason |
| 23 | Module ingest hard-rejects non-ARM externals | A one-byte ELF check that catches real shipping breakage, including inside ORHACK itself |
| 24 | Chain auto-assembly skill deferred, not dropped; catalog populates `tags` now | An explicit Prompt.md requirement. Deferring keeps scope sane; populating tags at ingest means no re-ingest later |
| 25 | Compiler always emits `s1 = routers/hybrid` and `s2 = clocks/transport`. Fixed **module identity only** — `s1`'s parameters remain the compile target for `input:`, `midi: {channel}` and `send:` | Both are structural — never `-empty-` in any shipped preset, and the router *is* the rack. But all per-chain router state lives inside `s1`'s param block, so freezing the slot must not be read as freezing its parameters |
| 26 | Transport is fully compiler-defaulted; `midiin = 1`, nothing tempo-related in song files | The DAW's MIDI clock is the master for tempo, start and continue. Signature stays at default 4 — MIDI clock cannot transmit it, and it is inert with sequencers out of scope |
| 27 | Community module category mapped from Patchstorage category, with per-entry override | Role cannot be derived from the patch — signal I/O does not discriminate. Category is functionally inert, so a bad guess costs only device-browser tidiness |
| 28 | All slot-group capacities are hard compile errors | Chains, sends, master and mod-sources all have caps. Validating only the chain case left three identical failure modes undefined |
| 29 | Offline handling split: cannot-check skips silently, cannot-install aborts | Prompt.md's "never blocks push" was written about update checks. A module in the lock that is absent and unreachable cannot produce a working preset |
| 30 | Chain letters assigned in two declaration-order passes: 4-slot chains claim B then D, then every remaining chain claims the next free letter in the order A, C, B, D | Pass 2 must be able to use B and D — restricting small chains to A and C strands them while 4-slot letters sit empty. Totality is what makes the "song file plus lock determines output" invariant survive a cold rebuild |
| 31 | Chain note channel defaults to declaration position; explicit override allowed, `0` = omni; overrides never renumber other chains | The user wants omni available for global note parts. Non-renumbering keeps the DAW mapping of untouched chains stable when one chain is overridden |
| 32 | Multi-category uploads resolve by fixed precedence: sampler > sequencer > synthesizer > effect > utility | 27 of 100 sampled uploads have categories mapping to conflicting folders. Without a rule, ingest is non-deterministic — and category is part of `moduleType` |
| 33 | On an omni chain, every module `midi:` entry must state its channel explicitly | The CC key space is `channel * 128 + cc` for channels 1-16. Defaulting from an omni chain would build a key no real message can match, silently killing the automation |
| 34 | Omni chains are exempt from the shared-channel lint | An omni chain overlaps every numbered chain by design; flagging it would be noise |
| 35 | The Organelle's physical keyboard is not a chain input and gets no schema field | It routes to one global active destination (`r-main-dest`), gated off by default — not a per-chain gate. Prompt.md grouped it with guitar and MIDI note in; that grouping does not match the device |
| 36 | Adopted presets derive chain and send names from their contents — first module's catalog key, `@source` dropped | The device stores no names. Deriving from contents reads meaningfully at once and never embeds a slot letter, which `chain-a` would. Empty chains and sends are omitted rather than named |
| 37 | A recorded chain name→letter binding is authoritative; the compiler assigns letters only where no binding exists | Without this, an adopted song recompiles to different letters than the device had (a 3-module chain on D moves to C) and reports drift on the very next pull, on a song nobody edited |
| 38 | Adoption snapshots the observed `params.json` into `.rig/state/last-pushed/` | An adopted song is never pushed — it is already correct on the device — so without this it has no drift baseline and the next pull reports the whole preset as drift |
| 39 | Sample selection is reverse-mapped from `samp_source`/`samp_select`, never left to catalog defaults | `samp_source`'s default of `0` decodes to "nothing selected". Omitting the `sample:` field would make the next push replace a working sampler chain with silence |
| 40 | Push mirrors sidecar `.txt` files inside a preset directory with deletions, not additively | Sidecars are slot-keyed, not module-keyed. Changing a slot's occupant between pushes leaves the previous module's arrays for the new one to read — the staleness bug #1 exists to prevent, caused by the compiler |
| 41 | Mono physical input L only; YAML exposes input/output gain, balance, optional width, and per-module `note-thru` | Covers device-side mixing without exposing unused stereo input pan; balance+width losslessly represent both output pans |
| 42 | Generated catalog is committed and refreshed explicitly; CI replays frozen fixtures | Push stays offline and catalog changes remain deterministic and reviewable |
| 43 | Broken/destructive lint findings are errors; musical oddities are warnings | Prevents silent failure without outlawing intentional routing |
| 44 | Push uses a staged journal, backups, flushes, and hash verification | Multiple fixed preset/media roots cannot be globally atomic; journaled recovery is the strongest available guarantee |
| 45 | Verify ORHACK; never install or repair it | Its fixed 2,353-file manifest supports offline verification; reimplementing `deploy.sh` adds risk without recurring value |
| 46 | Channel 16 is reserved; YAML `program` maps directly to Program Change | MEC has no MIDI load-by-name path; numeric prefixes and silent gaps preserve direct indices |
| 47 | Runtime `/tmp/data` and `/tmp/media` are card symlinks | Organelle_OS creates them from the active user directory at patch launch |
| 48 | Stateful-module defaults come from pinned ORHACK `Init` sidecars; unknown persistence is rejected | Exact shipped templates are safer and smaller than reimplementing Pd array initialisation |
| 49 | Program prefixes are zero-padded to three digits; two songs sharing a `program` is a hard error | MEC's directory sort is lexicographic, so `10-` precedes `2-` and every song above program 9 would load the wrong preset. Fixed width also makes the order locale-independent, which nothing else about the scan guarantees. A shared value makes one song unreachable by Program Change |
| 50 | A gap placeholder is a preset holding `s1`, `s2` and 22 `-empty-` slots, with no sidecar files | It has to be loadable — Program Change can land on one. Empty slots mean no module reads an array, so a placeholder cannot propagate the staleness of #1 |
| 51 | Push records the preset directory name and program it wrote, in `.rig/state/last-pushed/<song>.meta.json` alongside the params snapshot | Without it, push cannot tell a renamed song from a stranger, so the most ordinary edit — renaming a song file or changing its `program` — refuses the next push. A sidecar rather than a wrapper keeps `<song>.json` byte-identical to the card artifact, which is what makes hash verification and the drift diff cheap |
| 52 | Orphan presets split three ways: recorded and song file deleted → removed on a plain push; unrecorded → refuse, `--force` deletes; matched → updated. Supersedes the two-way split in #18 | Deleting a song file is an unambiguous instruction. Lumping it with device-made experiments forced one blunt `--force` to cover both, so retiring a song also destroyed every unmerged experiment on the card |
| 53 | Push repairs `rack.json`'s `currentPreset` only when its own writes leave it dangling — to the lowest-numbered managed preset, else `Init` | `currentPreset` is the device's performance cursor, not repo state; rewriting it every push would discard where the band left off. But renaming or deleting the loaded preset breaks a pointer the tool broke. A dangling pointer boots into `main.pd`'s hardcoded default rack — including two module paths that do not exist — and the next on-device save writes that rack back under the missing name. Leaving one behind manufactures drift, and an unloadable preset with it |
| 54 | The repo is authoritative for song *existence*; the device is authoritative only for parameter *values* | Pull may change what a song says, never whether it exists. Deriving deletion from device state would make the hardest thing to recover — a `.yaml` nobody has a copy of — destroyable by a missing directory |
| 55 | Pull matches card presets to songs by the recorded directory name, never by reconstructing it from the song file. A recorded preset missing from the card warns; *all* missing is a hard error | Reconstruction breaks on a repo rename that has not been pushed yet, and pull-before-push makes that the normal order, not an edge case. One missing preset is news; every one missing is the wrong card, and mirror-with-deletions makes that unrecoverable |
| 56 | `rig upgrade` never rewrites `last-pushed/`; it refuses when a parameter slug used by any song changes its underlying id | The card is unchanged by an upgrade, so rewriting the baseline would fabricate it and hide real device edits. Slug→id drift is the silent hazard: `amount-3` still resolves after an upstream reorder, to a different parameter. `fission` shares labels across 83 of 97 parameters, so this is routine, not hypothetical |
| 57 | Push reconciles installed modules by content hash against the lock, and refuses a *selective* push when the lock changed since the last push | Installing only what is missing would leave an upgraded module at its old version on the card while the compiler emits for the new one. Reconciling is repo-wide because one card holds one copy — so scoping it to a song selection would leave the card matching no commit. Refusing forces the wide operation to be deliberate |
| 58 | Chain bindings stay name-keyed; push detects an un-commanded hand rename and refuses | Position-keying would make renames free but silently reassign letters on reorder. With no hardware feedback channel, a refused push naming the fix beats a preset that loads on the wrong letters and only surfaces at the next pull |
| 59 | `push`/`pull --dry-run` require the mounted card and share the real command's preconditions and refusals | The destructive set — deletions, renames, module replacement — is computed from card-versus-repo. A cardless dry-run would report nothing destructive because it never looked. `rig lint` already serves the offline check |
| 60 | Catalogue by module content, not archive size: an upload contributes one entry per module. Exclude only rack redistributions, detected by a `main.pd` at the package root | Archive cardinality was a proxy for "is this the whole rack", and it caught the wrong things. `sequencers-bpm` (7) and `orac-cvtools` (8) are ordinary module packs, and single-module re-uploads of the *same* cvtools modules are already catalogued — so excluding the pack while keeping its siblings was incoherent. `main.pd` is the rack entry point and no chain-slot module has one; it separates all five measured multi-module archives cleanly, and it is the same signal that already identifies the 14 mis-tagged standalone patches. Measured: +15 modules, 200 entries, still zero qualified key collisions and no built-in runtime path collision |
| 61 | No simulated-OS tier. Validation is static CI plus a hardware check | A QEMU user-mode ARM32 image, a sanitised rootfs, registry hosting, per-module Pd harnesses and a DSP oracle is vendor-scale test infrastructure for a rig of one device. Static already rejects wrong-arch ELF, missing Pd objects and undefined symbols, which is most of "this module cannot load". The residual gap — loads but errors at runtime — is caught by the hardware check reading the device's own log, one rehearsal later instead of one pull request earlier |
| 62 | Hardware validation is a hand-run laptop command, not CI | Requires no second S2, no self-hosted runner, no protected environment and no attestation chain. Attestation existed to make CI evidence provable to a third party; run from the band's own laptop there is no third party. Cost of the lab was owning hardware that never plays a show |
| 63 | Nothing validates DSP, audio quality or silence, at any tier | Scope call: what the band wants automated is load cost and load time. A per-role oracle needs a role for all 200 catalog entries plus stimulus and threshold design per role, to assert something an ear settles in one bar. Recorded explicitly so no report is ever read as "this sounds right" |
| 64 | The hardware check is read-only, so there is no backup, restore or quarantine | Verified in `mec`: `loadFilePreset` writes nothing, `rack.json` is written only by an explicit `savesettings`, `params.json` only by `savePreset`. Forbidding CC 102 and every save command keeps that true. This deletes the most dangerous machinery in the plan — a restore path that could destroy the card it was protecting |
| 65 | Device access is the built-in OS 5.1 web API only — no SSH, no sudo, no installed agent | SSH ships disabled on S2 images; the unauthenticated web app already grants strictly more, including a shell. Installing nothing means nothing to version and no perturbation of the runtime being measured. Consequence, stated rather than assumed: the check is only safe on a network you control, which is already true of the device |
| 66 | Loads are triggered by MIDI Program Change on channel 16, not OSC load-by-name | OSC can load by name and MIDI cannot, which is exactly why MIDI is the right test input: it exercises the zero-padded prefix and gap-placeholder scheme the compiler depends on. Loading by name would hide an ordering bug |
| 67 | Hard-fail on Pd load errors and ALSA underruns; warn at 20% regression from a committed baseline; no absolute gates | Errors and xruns are unambiguous and need no calibration. A CPU or timing ceiling chosen before any real measurement exists either blocks a working song or never fires, and the 20-repetition calibration ritual only made sense as input to a release gate that no longer exists |
| 68 | No symbol or Pd-object resolution in static validation. Tier 1 is the catalog gate plus schema lint, nothing more | The check needed a pinned Pd/rootfs symbol manifest, which was going to be a by-product of extracting the OS image for the simulated tier. #61 removed the tier and left the check standing on a source that no longer existed. Rebuilding it from Debian packages was possible but is a manifest to build, commit, refresh and keep in step with the subject — real machinery for a failure the hardware check now catches anyway, as a `couldn't create` line in the device log. Cost: an unresolvable external or object is found at rehearsal rather than on a pull request |
| 69 | The compiler emits a verified default sidecar set only for `mod-sources/morpher`; a song placing any of `sequencers/{overdrum,overflow,clips,polystep}`, or a community module ingest already flagged as stateful, is a hard `UNVERIFIED_STATEFUL_MODULE` compile error | `Init`, decision #48's canonical source, does ship default content for *some* of what `overdrum`/`overflow` read (`loop-*`, `metric-*`, `step-seq-{note,vel,length}-*`), but reading `seq3.pd`'s `save-the-txts` subpatch shows both also read `<slot>-slot-tracker.txt` (triggered by `r loadbang-\$1` → `del 2` → `route 69`, line 639) and `<slot>-seq<n>x.txt` (triggered directly by the subpatch's own `read-bang` inlet, line 595) unconditionally on every load — and `Init` ships neither anywhere, across all 24 slots; `jam`'s two `slot-tracker.txt` files sit on documented-stale `-empty-` slots, not a shipped default. `clips` and `polystep` have no verified template for anything they read. Emitting only the verified families would silently reproduce decision #1's staleness bug for the other two; refusing does not |

| 70 | The reverse mapper aborts a song rather than editing it when: a decoded CC or channel would fail `rig.song.validate`'s own hard checks (CC 1/74, channel 16, an out-of-range channel); a slot's module identity no longer matches what the song declares; drift touches mod-bus routing or a CC mapping outside a chain module; or a sample selects the shared `samples/`/`loops`/`synths` folders. Program is never reverse-mapped | Reserved-value drift: the device can hold a value the compiler would never have produced — that is the whole premise of drift — so a decoded CC/channel can fail validation; writing it into the song anyway would hand back a file that fails later, in a more confusing place, so it aborts instead. Module identity: `rig.song.model`'s `ModuleSlot.key`/`ModuleUse.key` *can* express a slot's occupant, so this is not a missing-field case — capturing a change would mean re-deriving that slot's whole parameter set against the newly-observed module, which is emitting a new reference, not editing what moved. Scope stops there because the rig's owner does not edit module placement on the device (project owner's ruling), not because the model has nowhere to put it. Mod-bus routing and a CC mapping outside a chain module's `midi:` block genuinely have no schema field anywhere. Program: `reverse_map_song` only ever receives two `params.json`-shaped dicts, never a directory name, and pull matches a preset to its song by the *recorded* directory name — so a changed program surfaces earlier, as a recorded-preset-missing warning, before this function would ever see it; left out on that basis, not because any doc was silent on it |

## Superseded from Prompt.md

- **Auto-install newest module version on push** → #20.
- **"Stock Organelle default patches" as a module provenance type** → removed.
  Stock Organelle patches are standalone `main.pd` patches and cannot occupy a
  chain slot.
- **`Patches/0RHACK/orac.json` as the live config** → wrong. See
  [platform/state.md](platform/state.md).
- **"CC numbers never appear in the YAML schema"** → partially overridden. CC
  numbers *do* appear, in per-module `midi:` blocks. They have to: the DAW file's
  automation targets a concrete CC, and no alias can be invented for a number the
  musician already chose in their DAW. What the schema does keep hidden is the
  encoded key (`channel * 128 + cc`), slot ids, `moduleType` paths, parameter ids
  and `kit-N` — the identifiers a musician has no other reason to know.
- **"MIDI note in configurable per chain"** → overridden by #9. `r-chin-midigate-N`
  is a real per-chain gate, but it is compiled always-on. Enabling costs nothing
  (message-domain spigot, no DSP), and a chain with no note-reading module is
  unaffected either way.
- **"Empty `tags` field reserved for future use"** → populated at ingest per
  #24, avoiding catalog re-ingest for auto-assembly.
- **"Roll back to last-known-good cached copy" on transfer failure** → satisfied
  by #44, not by a separate host-side download cache. Push's staged journal and
  on-card backups *are* the last-known-good copy, and they are the copy that
  matters: a cached archive on the laptop cannot restore a card that failed
  mid-swap. Module archives are re-fetched when needed.
- **"Sample playback" as a per-chain input type** → it is not an input. Sample
  playback is a module (`samplement@orhack`) occupying a chain slot, so it is
  selected like any other module rather than gated like guitar audio or MIDI
  note in. Same category of correction as #35 for the keyboard.
